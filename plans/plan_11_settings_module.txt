Expense Tracker - Module 8: Settings Module Plan
==================================================

Module Name: Settings
File: plan_11_settings_module.txt

---


Overview
--------
Allows users to configure application preferences like currency, date format,
email notifications, and data management options. Settings are user-specific
and applied throughout the application.

---


Pages / Views
-------------

1. Settings Page
   Path: views/users/settings.php
   Shows: settings form with multiple sections

---


Controllers
-----------

1. SettingController.php
   Methods:
   - index()       -> show settings page
   - update()      -> handle POST, validate, save settings

---


Models Used
-----------

1. User.php
   Methods:
   - getSettings($user_id)
   - updateSettings($user_id, $data)

2. Setting.php (if using separate settings table)
   Methods:
   - getByKey($user_id, $key)
   - set($user_id, $key, $value)

NOTE: For simplicity, settings can be stored as columns in users table or
in a separate settings table. Recommended: use users table columns for
simple settings (currency, date_format, email_notifications).

---


Settings Sections
-----------------

1. General Settings
   - Currency: dropdown, required
     Options: USD ($), EUR (€), GBP (£), INR (₹), JPY (¥), CAD (C$), AUD (A$), etc.
     Store as 3-letter ISO code (USD, EUR, etc.)
   - Date Format: dropdown, required
     Options:
       YYYY-MM-DD (2026-07-28)
       DD-MM-YYYY (28-07-2026)
       MM-DD-YYYY (07-28-2026)
       DD/MM/YYYY (28/07/2026)
       MM/DD/YYYY (07/28/2026)
     Store as PHP date format string (Y-m-d, d-m-Y, etc.)

2. Notification Settings
   - Email Notifications: checkbox, default checked
     - Receive email when expense/income added (optional)
     - Receive weekly summary email (optional)
     - Receive monthly report email (optional)

3. Display Settings
   - Transactions Per Page: dropdown, default 10
     Options: 10, 25, 50, 100
   - Default Transaction Type: radio buttons
     Options: Expense, Income
     Used when opening quick add form

4. Data Management
   - Export All Data: button -> triggers CSV export of all user data
   - Clear All Data: button -> opens confirmation modal
     - Deletes all transactions, categories (except defaults)
     - Resets settings to default
     - Cannot be undone

Data Export
-----------

Export All Data Button:
   - Generates CSV file with:
     - transactions.csv (all user transactions)
     - categories.csv (all user categories)
     - settings.csv (user settings)
   - ZIP all files and download
   - Filename: expense_tracker_data_YYYY-MM-DD.zip

Export Format (CSV):
   transactions.csv:
     id, type, amount, description, date, category, created_at
     1, expense, 50.00, Lunch, 2026-07-28, Food, 2026-07-28 12:00:00

   categories.csv:
     id, name, type, icon, color, is_default
     1, Food, expense, utensils, #dc3545, 1

Currency Symbol Mapping:
   USD -> $
   EUR -> €
   GBP -> £
   INR -> ₹
   JPY -> ¥
   CAD -> C$
   AUD -> A$

Storage:
   - Store currency code in users.currency column
   - Use ISO 4217 3-letter codes

---


Date Format Handling
--------------------

Display:
   - Format dates throughout app using user's preference
   - Example: date('Y-m-d') for YYYY-MM-DD

Settings Storage
----------------

Option A: Columns in users table (Recommended for simple settings)
   - currency (VARCHAR 3)
   - date_format (VARCHAR 20)
   - email_notifications (TINYINT)
   - transactions_per_page (INT)
   - default_transaction_type (ENUM)

Option B: Separate settings table (for many settings)
   - id, user_id, key, value, created_at, updated_at
   - More flexible, easier to add new settings

Recommended: Use Option A for this project as settings are few and well-defined.

IMPORTANT: Security Implementation Standards
==============================================

This module MUST follow these security practices in implementation:

1. Prepared Statements: ALL database queries MUST use PDO prepared statements with bound parameters. Never concatenate user input into SQL queries.
   Example: $stmt = $pdo->prepare("SELECT * FROM transactions WHERE user_id = :user_id AND date >= :date_from");
            $stmt->execute(['user_id' => $user_id, 'date_from' => $date_from]);

2. Input Sanitization: ALL user inputs must be sanitized before validation and database insertion.
   Example: $amount = filter_input(INPUT_POST, 'amount', FILTER_SANITIZE_NUMBER_FLOAT, FILTER_FLAG_ALLOW_FRACTION);
            $description = filter_input(INPUT_POST, 'description', FILTER_SANITIZE_SPECIAL_CHARS);

3. Output Escaping: ALL dynamic content rendered in views MUST be escaped using htmlspecialchars() to prevent XSS.
   Example: echo htmlspecialchars($transaction['description'], ENT_QUOTES, 'UTF-8');
            echo htmlspecialchars($category['name'], ENT_QUOTES, 'UTF-8');

4. Authorization Checks: Verify the logged-in user owns the resource before any operation.
   Example: if ((int)$transaction['user_id'] !== (int)$_SESSION['user_id']) { http_response_code(403); exit('Forbidden'); }

5. CSRF Protection: All POST/PUT/DELETE forms must include and validate CSRF tokens.
   Example: if (!hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) { http_response_code(403); exit('Invalid CSRF token'); }

6. File Upload Security: Validate MIME type by extension and content, use random filenames, store outside web root if possible.
   Example: $allowed = ['jpg','jpeg','png','gif'];
            $ext = strtolower(pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION));
            if (!in_array($ext, $allowed)) { reject; }
