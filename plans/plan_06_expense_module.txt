Expense Tracker - Module 3: Expense Management Module Plan
============================================================

Module Name: Expense Management
File: plan_06_expense_module.txt

---


Overview
--------
Allows users to create, view, edit, delete, and search their expense transactions.
Users can attach receipt images to expenses and filter expenses by date, category, and amount.

---


Pages / Views
-------------

1. Expense List Page
   Path: views/expenses/index.php (or list.php)
   Shows: filter form, expense table, pagination

2. Create Expense Page
   Path: views/expenses/create.php
   Shows: expense creation form with all fields

3. Edit Expense Page
   Path: views/expenses/edit.php
   Shows: pre-filled form to edit an existing expense

---


Controllers
-----------

1. ExpenseController.php
   Methods:
   - index()        -> show list page with filters and pagination
   - create()       -> show create form
   - store()        -> handle POST, validate, save expense
   - edit($id)      -> show edit form with pre-filled data
   - update($id)    -> handle PUT/PATCH, validate, update expense
   - destroy($id)   -> delete expense
   - getCategories() -> AJAX: get expense categories for dropdown

---


Models Used
-----------

1. Transaction.php
   Methods:
   - createExpense($user_id, $data)
   - updateExpense($id, $user_id, $data)
   - deleteExpense($id, $user_id)
   - findById($id, $user_id)
   - getAllExpenses($user_id, $filters, $page, $perPage)
   - getExpenseCount($user_id, $filters)

2. Category.php
   Methods:
   - getExpenseCategories($user_id)
   - getById($user_id, $id)

Expense List Page Details
--------------------------

Filter Form (top of page):
   - Date From: date input
   - Date To: date input
   - Category: dropdown (all expense categories)
   - Amount From: number input
   - Amount To: number input
   - Search: text input (search in description)
   - Reset Filters button
   - Apply Filters button

Table Columns:
   - Checkbox (for bulk delete, optional)
   - Date
   - Description
   - Category (with color indicator)
   - Amount (red color, formatted)
   - Receipt (icon/link if image exists)
   - Actions: Edit button, Delete button

Features:
   - Sortable columns (click header to sort by date/amount/category)
   - Pagination (10, 25, 50, 100 per page options)
   - "Add New Expense" button at top
   - Empty state: "No expenses found. Add your first expense!"
   - Bulk delete with confirmation (optional)
   - Export selected/filtered to CSV (optional)

---


Create Expense Page Details
----------------------------

Form Fields:
   - Amount: number input, required, min 0.01, step 0.01
   - Category: dropdown, required, populated with user's expense categories
   - Date: date input, required, default today's date
   - Description: textarea, optional, max 500 chars
   - Receipt Image: file input, accept image/*, optional
     - Preview shown after selection
     - Max file size: 2MB
     - Allowed types: jpg, jpeg, png, gif
     - Upload to uploads/receipts/ with unique filename
   - Submit button
   - Cancel button (redirects to expense list)

Validation:
   - Amount: required, numeric, > 0
   - Category: required, must be an expense category owned by user
   - Date: required, valid date, cannot be future date (optional)
   - Description: max 500 chars, optional
   - Receipt: file type check, file size check

Success: Redirect to expense list with success flash message
Failure: Redirect back with errors, retain form data

---


Edit Expense Page Details
--------------------------

Same form as create, pre-filled with existing data:
   - Load expense by id and user_id
   - Show 404 if not found or not owned by user
   - Pre-fill all fields
   - Show current receipt image if exists (with delete option)
   - Submit button says "Update Expense"
   - Delete button at bottom (with confirmation modal)

Validation:
   - Same as create
   - Category can be changed to any expense category

Success: Redirect to expense list with success flash message
Failure: Redirect back with errors

AJAX Endpoints
--------------

1. GET /expenses/categories
   Purpose: Get expense categories for dropdown
   Response: JSON array of {id, name, color}

2. POST /expenses/upload-receipt
   Purpose: Upload receipt image
   Request: multipart/form-data with image file
   Response: {success: boolean, path: string, message: string}
   Validation: file type, file size (2MB max)

3. DELETE /expenses/delete-receipt
   Purpose: Delete receipt image from server
   Request: {transaction_id}
   Response: {success: boolean, message: string}

IMPORTANT: Security Implementation Standards
==============================================

This module MUST follow these security practices in implementation:

1. Prepared Statements: ALL database queries MUST use PDO prepared statements with bound parameters. Never concatenate user input into SQL queries.
   Example: $stmt = $pdo->prepare("SELECT * FROM transactions WHERE user_id = :user_id AND date >= :date_from");
            $stmt->execute(['user_id' => $user_id, 'date_from' => $date_from]);

2. Input Sanitization: ALL user inputs must be sanitized before validation and database insertion.
   Example: $amount = filter_input(INPUT_POST, 'amount', FILTER_SANITIZE_NUMBER_FLOAT, FILTER_FLAG_ALLOW_FRACTION);
            $description = filter_input(INPUT_POST, 'description', FILTER_SANITIZE_SPECIAL_CHARS);

3. Output Escaping: ALL dynamic content rendered in views MUST be escaped using htmlspecialchars() to prevent XSS.
   Example: echo htmlspecialchars($transaction['description'], ENT_QUOTES, 'UTF-8');
            echo htmlspecialchars($category['name'], ENT_QUOTES, 'UTF-8');

4. Authorization Checks: Verify the logged-in user owns the resource before any operation.
   Example: if ((int)$transaction['user_id'] !== (int)$_SESSION['user_id']) { http_response_code(403); exit('Forbidden'); }

5. CSRF Protection: All POST/PUT/DELETE forms must include and validate CSRF tokens.
   Example: if (!hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) { http_response_code(403); exit('Invalid CSRF token'); }

6. File Upload Security: Validate MIME type by extension and content, use random filenames, store outside web root if possible.
   Example: $allowed = ['jpg','jpeg','png','gif'];
            $ext = strtolower(pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION));
            if (!in_array($ext, $allowed)) { reject; }
