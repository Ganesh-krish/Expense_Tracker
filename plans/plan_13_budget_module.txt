Expense Tracker - Module 10: Budget Management Module Plan
============================================================

Module Name: Budget Management
File: plan_13_budget_module.txt

---


Overview
--------
Allows users to set monthly budget limits per expense category.
Users can track their spending against budgets and receive alerts
when they are close to or exceed their budget limits.

NOTE: This is an optional module. Can be implemented in Phase 2 if Phase 1
takes too long. The database design already includes the budgets table.

---


Pages / Views
-------------

1. Budgets List Page
   Path: views/budgets/index.php
   Shows: current month budgets, progress bars, alerts

2. Create/Edit Budget Page
   Path: views/budgets/create.php or edit.php (or modal)
   Shows: form to set budget for a category and month

---


Controllers
-----------

1. BudgetController.php
   Methods:

   - create()          -> show create budget form

Budgets List Page Details
--------------------------

Layout:
   - Month selector at top (dropdown to change month)
   - Budget cards or table for each expense category
   - Progress bar for each category showing spending vs budget
   - Alert indicators for exceeded/near-limit budgets
   - "Set Budget" button

Budget Card Design:
   - Category name with icon and color
   - Budget amount
   - Spent amount (calculated from transactions)
   - Remaining amount
   - Progress bar (percentage of budget used)
     - Green: 0-70% used
     - Yellow: 70-90% used
     - Red: 90-100% used
     - Full red: 100%+ (exceeded)
   - "Edit" button
   - "Delete" button
   - Alert badge if exceeded

Month Selector:
   - Dropdown with months: "July 2026", "June 2026", etc.
   - Default: current month
   - Can view past months (read-only) or future months (editable)

---


Create/Edit Budget Form
-----------------------

Fields:
   - Category: dropdown, required, expense categories only
   - Month: date input (month picker), required, default first day of current month
   - Budget Amount: number input, required, min 0.01
   - Submit button
   - Cancel button

Month Input:
   - Use month picker (YYYY-MM format)
   - Store as first day of month in database (2026-07-01)
   - Default: current month (first day)

Validation:
   - category_id: required|exists:categories,id|type:expense
   - month: required|date|date_format:Y-m-d
   - amount: required|numeric|min:0.01

Unique Constraint:
   - One budget per user per category per month
   - If budget already exists for selected category and month, show edit form instead

---


Budget Progress Calculation
---------------------------

For each category with a budget:
   - spent = sum of expense transactions for that category in that month
   - remaining = budget_amount - spent
   - percentage = (spent / budget_amount) * 100

Display:
   - Progress bar width = min(percentage, 100)%
   - Color based on percentage thresholds
   - Show exact percentage text

---


Budget Alerts
-------------

Alert Levels:
   1. Warning (70-90% used): Yellow indicator
      Message: "You've used {percentage}% of your {category} budget"

   2. Danger (90-100% used): Orange indicator
      Message: "You're almost at your {category} budget limit"

   3. Exceeded (100%+ used): Red indicator
      Message: "You've exceeded your {category} budget by {over_amount}"

Alert Display:
   - Alert badges on budget cards
   - Notification bell icon in navbar with count
   - Alert banner on dashboard (optional)

AJAX Endpoints
--------------

1. GET /budgets/progress
   Purpose: Get budget progress for all categories for a month
   Request: ?month=YYYY-MM-DD
   Response: JSON array of {category_id, category_name, budget_amount, spent, remaining, percentage, status}

2. GET /budgets/alerts
   Purpose: Check for any budget alerts
   Request: ?month=YYYY-MM-DD
   Response: JSON array of alerts {level, category, message}

3. GET /budgets/categories
   Purpose: Get expense categories for dropdown
   Response: JSON array of {id, name, color}

Database Logic
--------------

Table: budgets
   - id, user_id, category_id, amount, month, created_at, updated_at

Month Storage:
   - Store as DATE type: first day of month (YYYY-MM-01)
   - Use for filtering and grouping
   - Example: July 2026 = '2026-07-01'

Budget Period:
   - Budgets are monthly by design
   - Cannot set weekly or yearly budgets (out of scope)
   - Each month has independent budgets

---


Budget Calculation Logic
------------------------

When user views budgets for a month:
   1. Fetch all budgets for user and selected month
   2. For each budget:
      a. Get category details
      b. Calculate total expenses for that category in that month
      c. Calculate percentage used
      d. Determine status (normal, warning, danger, exceeded)
   3. Display budget cards with progress

When user adds/edits/deletes expense:
   1. Check if expense category has a budget for that month
   2. If yes, recalculate budget progress
   3. If exceeded, trigger alert (optional)

IMPORTANT: Security Implementation Standards
==============================================

This module MUST follow these security practices in implementation:

1. Prepared Statements: ALL database queries MUST use PDO prepared statements with bound parameters. Never concatenate user input into SQL queries.
   Example: $stmt = $pdo->prepare("SELECT * FROM transactions WHERE user_id = :user_id AND date >= :date_from");
            $stmt->execute(['user_id' => $user_id, 'date_from' => $date_from]);

2. Input Sanitization: ALL user inputs must be sanitized before validation and database insertion.
   Example: $amount = filter_input(INPUT_POST, 'amount', FILTER_SANITIZE_NUMBER_FLOAT, FILTER_FLAG_ALLOW_FRACTION);
            $description = filter_input(INPUT_POST, 'description', FILTER_SANITIZE_SPECIAL_CHARS);

3. Output Escaping: ALL dynamic content rendered in views MUST be escaped using htmlspecialchars() to prevent XSS.
   Example: echo htmlspecialchars($transaction['description'], ENT_QUOTES, 'UTF-8');
            echo htmlspecialchars($category['name'], ENT_QUOTES, 'UTF-8');

4. Authorization Checks: Verify the logged-in user owns the resource before any operation.
   Example: if ((int)$transaction['user_id'] !== (int)$_SESSION['user_id']) { http_response_code(403); exit('Forbidden'); }

5. CSRF Protection: All POST/PUT/DELETE forms must include and validate CSRF tokens.
   Example: if (!hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) { http_response_code(403); exit('Invalid CSRF token'); }

6. File Upload Security: Validate MIME type by extension and content, use random filenames, store outside web root if possible.
   Example: $allowed = ['jpg','jpeg','png','gif'];
            $ext = strtolower(pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION));
            if (!in_array($ext, $allowed)) { reject; }

Phase Recommendation
---------------------

This module is marked as optional because:
   1. Core functionality (Auth, Dashboard, Expense, Income, Category, Reports, User, Settings, Search) is complete without it
   2. Requires additional UI complexity (progress bars, alerts, notifications)
   3. Database schema already supports it (budgets table exists)
   4. Can be added in Phase 2 after core modules are stable

Recommended priority: Phase 2 (after all core modules are tested and working)
