Expense Tracker - Module 5: Category Management Module Plan
=============================================================

Module Name: Category Management
File: plan_08_category_module.txt

---


Overview
--------
Allows users to create, edit, and delete custom categories for both income and expenses.
The system comes with default categories pre-installed. Users can add their own categories
with custom names, colors, and icons. Categories are used in expense and income forms.

---


Pages / Views
-------------

1. Categories List Page
   Path: views/categories/index.php (or list.php)
   Shows: tabs for Income/Expense, category cards/table, add button

2. Create Category Page/Modal
   Path: views/categories/create.php (or modal partial)
   Shows: form to create new category

3. Edit Category Page/Modal
   Path: views/categories/edit.php (or modal partial)
   Shows: form to edit existing category

---


Controllers
-----------

1. CategoryController.php
   Methods:
   - index()           -> show categories list with tabs
   - create()          -> show create form/modal
   - store()           -> handle POST, validate, create category
   - edit($id)         -> show edit form/modal with data
   - update($id)       -> handle PUT/PATCH, validate, update category
   - destroy($id)      -> delete category
   - getByType($type)  -> AJAX: get categories by type (income/expense)

---


Models Used

1. Category.php
   Properties: id, user_id, name, type, icon, color, is_default, created_at, updated_at
   Methods:

   - findById($id, $user_id)

Create Category Form
---------------------

Fields:
   - Name: text input, required, max 50 chars
   - Type: radio buttons (Income / Expense), required, default based on active tab
   - Icon: dropdown or icon picker, required, default generic icon
     Options: briefcase, laptop, chart-line, gift, utensils, bus, home, bolt, film, shopping-cart, heart, graduation-cap, ellipsis-h, etc.
   - Color: color picker, required, default random or #000000
   - Submit button
   - Cancel button

Validation:
   - name: required, string, max 50, unique per user per type
   - type: required, in: income, expense
   - icon: required, string
   - color: required, valid hex color (#RRGGBB)

Success: Redirect to categories list with success message
Failure: Redirect back with errors

---


Edit Category Form
------------------

Same form as create, pre-filled:
   - Load category by id and user_id
   - Show 404 if not found or not owned by user
   - Cannot edit default categories (show message or hide edit button)
   - Pre-fill name, type, icon, color
   - Submit button says "Update Category"
   - Delete button shown (with confirmation)

Validation:
   - Same as create
   - Name must be unique excluding current category

---


Delete Category
----------------

Confirmation Modal:
   - "Are you sure you want to delete this category?"
   - Show category name and icon
   - Warning: "Transactions using this category will not be deleted"
   - Confirm and Cancel buttons

Behavior:
   - Soft delete or hard delete (recommended: hard delete)
   - Transactions with this category keep the category name as text (or set to NULL/Other)
   - Cannot delete default categories (show error)
   - Success: redirect to list with success message

AJAX Endpoints
--------------

1. GET /categories/get-by-type
   Purpose: Get categories filtered by type for dropdowns in expense/income forms
   Request: ?type=expense or ?type=income
   Response: JSON array of {id, name, color, icon}

2. POST /categories/check-name
   Purpose: Check if category name already exists for user
   Request: {name, type, category_id (optional for edit)}
   Response: {exists: boolean}

Default Categories Behavior
----------------------------

On user registration:
   - Create all default categories for the new user
   - Set is_default = 1, user_id = new user's id
   - User can rename or delete these if needed

Default category insertion:
   - Done in User model afterCreate or in a migration/seeder
   - Or in AuthController after successful registration

Access Control
--------------

- Users can only manage their own categories
- Default categories (is_default = 1) can be edited but not deleted
- Users cannot access other users' categories
- If a category is deleted, transactions retain the category name as text

IMPORTANT: Security Implementation Standards
==============================================

This module MUST follow these security practices in implementation:

1. Prepared Statements: ALL database queries MUST use PDO prepared statements with bound parameters. Never concatenate user input into SQL queries.
   Example: $stmt = $pdo->prepare("SELECT * FROM transactions WHERE user_id = :user_id AND date >= :date_from");
            $stmt->execute(['user_id' => $user_id, 'date_from' => $date_from]);

2. Input Sanitization: ALL user inputs must be sanitized before validation and database insertion.
   Example: $amount = filter_input(INPUT_POST, 'amount', FILTER_SANITIZE_NUMBER_FLOAT, FILTER_FLAG_ALLOW_FRACTION);
            $description = filter_input(INPUT_POST, 'description', FILTER_SANITIZE_SPECIAL_CHARS);

3. Output Escaping: ALL dynamic content rendered in views MUST be escaped using htmlspecialchars() to prevent XSS.
   Example: echo htmlspecialchars($transaction['description'], ENT_QUOTES, 'UTF-8');
            echo htmlspecialchars($category['name'], ENT_QUOTES, 'UTF-8');

4. Authorization Checks: Verify the logged-in user owns the resource before any operation.
   Example: if ((int)$transaction['user_id'] !== (int)$_SESSION['user_id']) { http_response_code(403); exit('Forbidden'); }

5. CSRF Protection: All POST/PUT/DELETE forms must include and validate CSRF tokens.
   Example: if (!hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) { http_response_code(403); exit('Invalid CSRF token'); }

6. File Upload Security: Validate MIME type by extension and content, use random filenames, store outside web root if possible.
   Example: $allowed = ['jpg','jpeg','png','gif'];
            $ext = strtolower(pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION));
            if (!in_array($ext, $allowed)) { reject; }
